STATE Topbar chip 1 — autonomous-system state from the state machine, highlighted while it is RUNNING
MISSION Topbar chip 2 — selected mission. REMOTE_CONTROL is the one that hands driving to a human over the network
ESP32 Topbar chip 3 — seconds since the ESP32 last said it is alive. Green while the messages keep arriving, red "ESP32 SILENT" once they stop, which means the dashboard is showing frozen numbers and nothing is driving the actuators. "ESP32 --" before the first message has been seen
SYS Topbar chip 4 — worst case of the readouts below, naming where the trouble is instead of only changing colour. Red for a steering sensor that is unreadable or was lost, an ESP32 out of memory, any task under 200 spare bytes, or a silent ESP32; amber for slow cone detection or a slow ESP32 link. The old I2C bus and magnet signal are left out on purpose — they are never populated on this board, so folding them in would peg the chip to a permanent false alarm

STEER Steering sensor (MT6701 read over PWM). OK, NO SIGNAL (missing right now), or SIGNAL LOST (was missing at some point — emergency brake fired, throttle blocked until the ESP32 reboots, even if the signal is back). SIGNAL LOST carries how long ago it tripped and whether the signal has since returned, so a leftover trip from an earlier boot is distinguishable from one happening now
OLD I2C SENSOR BUS The bus the previous board used to read its steering sensor (an AS5600). This board does not use it, so "not used" is the normal reading and never means something is broken
ESP32 FREE MEMORY Memory the ESP32 still has spare, in kB. Turns red when it runs low, which is the warning before the firmware starts rebooting on its own
MAGNET SIGNAL STRENGTH How strongly the old AS5600 saw its magnet (0–255, healthy 20–235). Not measured on this board, for the same reason as the old I2C bus
ESP32 SPARE TASK MEMORY How much working memory is left in the tightest of the ESP32's four jobs (comms / control / heartbeat / health), in bytes. Red under 200 — that job is close to overflowing and crashing the firmware
CONE DETECTION How many camera frames per second the cone detector gets through. Green above 30, amber 15–30, red under 15, where the kart is reacting to cones it saw a long time ago
ESP32 LINK Steering messages per second over the USB cable to the ESP32. Firmware target 100. Green from 80 up, amber 30–80, red under 30, where steering commands are arriving too slowly to control the kart smoothly
